# 轻循

参考用户提供的卡卡瘦界面制作的手机端页面原型。奶油纸感底色、深绿色文字、浅绿 / 鹅黄 / 珊瑚色卡片；包含今日、周期、记录、跟练和日历。首页直接从热量收支开始。

## 本地预览

使用 Node.js 22 或更新版本启动：`node server.cjs`，访问 http://127.0.0.1:4173 。请通过服务地址使用，避免直接双击 HTML 导致存储来源不同。

## DeepSeek 照片识别

将 `.env.example` 复制为 `.env`，填写 `DEEPSEEK_API_KEY`，然后重启服务。在「拍照记一餐」中选择照片，点击「识别这张照片」，核对或修改自动填写的食物、份量和估算热量后保存。没有密钥或识别失败时仍可手动填写。

按照 [DeepSeek 官方图像理解文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)，服务端调用 `deepseek-flash`，以 `image_url` 内容块传入压缩照片。密钥仅保留在服务端，不写入前端、浏览器数据库或 Git。只有主动点击识别时，照片才会经服务端转发至 DeepSeek；其他健康记录不随请求发送，服务端不保存照片。

GitHub Pages 页面已配置调用 Cloudflare Worker：`https://qingxun-ai.jeffchen9618.workers.dev/api/recognize`。需要在 Worker 部署 `cloudflare/worker.mjs`，设置 `DEEPSEEK_API_KEY` 和 `ACCESS_TOKEN` 两项 Secret。完整操作见 [云函数部署说明](cloudflare/README.md)。在线识别时填写个人访问口令，口令仅在当前页面内存中暂存。手动记录无需口令，记录仍保存在原网页的浏览器数据库中。

在 localhost 或 127.0.0.1 本地预览时，页面继续使用本机 Node 服务及 `.env`，不要求云端访问口令。本地服务默认只监听本机地址。

## 当前可体验

- 喝水快捷记录、目标与提醒偏好设置。
- 经期日期录入与粗略阶段估算、身体感受记录。
- 饮食照片选择与压缩预览、DeepSeek 食物 / 份量 / 热量识别，以及手动填写和修正。
- 身体档案中的身高、体重及每日体重记录支持小数，例如 165.25 cm、60.55 kg。
- 首页体重趋势线，围度入口进入后展示胸围、腰围、臀围、大腿围、上臂围、小腿围的独立记录和趋势线。趋势使用最近 30 次真实记录，按实际日期间距绘制；只有一条记录时只显示点，不伪造历史。
- 运动总打卡与肩背、臀腿、体态、拉伸四类彩色独立勾选；类别勾选会同步当天运动状态，撤销总打卡会清除当天类别勾选。
- B 站（粉色）/ 抖音（绿色）链接收藏；可从抖音分享文字提取链接。分类为全部、肩背、臀腿、体态、拉伸；旧的全身收藏自动迁到体态，腿臀迁到臀腿。
- 手动记录 Apple Watch / 健康 App 的当天静息能量与活动能量。总消耗仅把两者相加一次，不再次加上单次训练消耗；饮食与消耗均确认全天完整后显示估算热量缺口，缺少数据时不输出全天结论。
- 月历切换、日期记录回看；经期粉色、卵泡期绿色、黄体期黄色、黄体后期蓝色，与周期页一致。选中日期保持阶段底色，用轮廓标记。
- 每次输入新的经期开始日会保留以前的周期记录；同一天重新填写会更新该记录。只着色已记录开始日之后一个设定周期的范围，不把历史无限循环外推。
- PWA 桌面图标、安装提示、离线页面缓存。首次需在线访问，所有资源使用相对路径，支持 GitHub Pages 项目子路径。
- 数据保存在当前浏览器 IndexedDB，自动迁移旧版 localStorage 记录并保留原数据；保存最近五次历史快照，防止其他页面覆盖较新记录。保存失败会显示提示。记录不会进入 Git 或上传服务器，主动识别的照片除外。

## 添加到手机桌面

线上页面需通过 HTTPS 访问。电脑本地的 `127.0.0.1` 网址无法直接在手机使用。

- iPhone：Safari 打开线上页面 → 分享 → 添加到主屏幕。
- 安卓：Chrome / Edge 打开线上页面 → 菜单 → 安装应用 / 添加到主屏幕。
- 首页底部的「添加到手机桌面」会在浏览器支持时请求安装，否则展示操作说明。最终添加需在用户手机完成。

可将本仓库 `main` 分支根目录设为 GitHub Pages 发布源；`.nojekyll` 已提供。常规项目网址为 `https://jeffzepher.github.io/lose_weight/`，以 GitHub 实际部署状态为准。

## 验证

首次运行 `npm install`，然后 `npm test`。测试包含阶段边界、历史周期、收藏链接、身高体重小数、围度、数据库迁移与刷新后读取、多页面冲突，以及模拟 DeepSeek 返回和错误处理。`fake-indexeddb` 仅用于测试，页面运行不需要安装依赖。真实识别需要有效密钥；尚需在真实 iOS / Android 设备验证安装与存储行为。

## 页面原型的边界

尚未接入蛋白质等营养分析、个性化热量目标算法、手机通知、账号与云端同步。Apple Watch 自动同步需要支持 HealthKit 的原生 iPhone App 和用户授权；网页 / PWA 仅提供手动录入。当前热量差额是记录数据的算术估算，并非精确测量或饮食处方。提醒设置不触发系统通知。照片和健康信息保存在本机浏览器，主动识别时照片会发送至 DeepSeek；清除浏览器数据后记录会丢失，请勿当作正式健康档案。

周期估算使用输入的平均周期与经期天数，黄体期边界按下次预期经期前约 14 天粗略划分，最后 5 天作为黄体后期展示；不确认排卵，不可用于避孕或诊断，超出预设周期时提示更新。未假设用户实际经期日期，也没有生成个体化热量处方。身体档案默认留空，年龄、身高、体重等个人信息由使用者在本机填写，不包含在公开源代码中。

当前原型不启用 16:8 断食，避免将参考产品中的功能直接变成用户默认计划。
